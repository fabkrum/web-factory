# GitHub Issues hold Requests, Specs and Tickets

A Site's Requests, Specs and Tickets live as GitHub issues in the Site's repository, not as markdown files in the repo, even though the Builders are full beginners. Markdown files would work offline, need no account and be readable by any model; we chose GitHub Issues so Builders learn the way real teams track work, because the workshops use GitHub anyway, and because the Ticket loop already reads its Tickets from issues. The cost is that a GitHub account and a logged-in `gh` are needed before the first Request.
